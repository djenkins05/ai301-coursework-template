# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Claim is specific, followable, and appropriately scoped | The candidate claim comment read against the issue title, description, and thread highlights. | Pass if the claim clearly identifies the reported issue or behavior being investigated and is specific enough that another person can understand and follow the intended investigation without needing clarification from the author. Fail if the claim is generic, ambiguous, covers unrelated work, or promises an unsupported fix, outcome, or deadline. | required |
| Environment is recorded | The repro report's environment record, read against any environment, version, platform, dependency, or configuration details relevant to the issue description and repo-facts block. | Pass if the report records enough of the relevant environment for another person to identify the conditions under which the attempt was made. Fail if a material environment detail needed to interpret or repeat the result is missing. | required |
| Reproduction steps are followable | The repro report's stated setup, commands, inputs, and actions, read against prerequisites in the issue description and repo-facts block. | Pass if a stranger with the referenced project can follow the reported sequence from the stated starting condition to the observed result without having to guess a material step, command, input, or prerequisite. Fail if reproducing the attempt requires guessing information that could change the outcome. | required |
| Evidence addresses the reported behavior | The repro report's observed artifacts, such as output excerpts, error messages, logs, screenshots described in the bundle, or other recorded results, read directly against the behavior the issue description reports. | Pass if the recorded evidence demonstrates the same behavior described by the issue, or demonstrates that the reported behavior did not occur under the documented reproduction attempt. Fail if the evidence demonstrates only a related or different behavior, or does not establish what happened. | required |
| Outcome matches the evidence | The repro report's stated conclusion read against its recorded steps and observed artifacts. | Pass if the stated result accurately reflects the evidence, including an honestly supported cannot-reproduce result. Fail if the report claims successful reproduction when the evidence does not show the reported behavior, claims cannot-reproduce without a meaningful documented attempt, or otherwise states a conclusion stronger than the evidence supports. | required |
| Repository conventions are respected | The candidate claim comment and repro report read against the repo-facts block, including the repository's contribution policy, bug-report expectations, communication requirements, and any AI-use or disclosure policy identified there. | Pass if the candidate comments satisfy every applicable repository requirement for this contribution, including any required disclosure of AI assistance. Fail if the comments violate an applicable stated convention or omit a disclosure or other requirement that the repository explicitly requires. | required |

## Verdict rule

Accept only if every required check passes. Reject if any required check fails or is unclear. An unclear grade counts as a failure because evidence that cannot be verified is not ready to post. Preferred checks, if added later, do not change the verdict.
